# 登録済みプロジェクトを画面から修復する

既存の `/experience` の「村の仕事」に、登録済みプロジェクト用の操作を接続する。
教材用の二ファイル修復とは別の対象だが、仕事・元の受信本文・採用知識・共有画面は共用する。
この経路も公開 main や利用者の本番へ自動適用する機能ではない。

準備済みの対象は名前で選び、編集するファイルと操作、検証の境界、使い捨ての適用先を
通常の表示で確認する。利用者がパス・内部 ID・JSON を入力する必要はない。
「この対象と範囲を確認した」を選んでから公開失敗の再現を開始する。
対象・仕事・登録の読み直しで確認は失効する。内部 ID やハッシュは折りたたんだ監査情報で読める。
通常の使い方案内は `/project-guide`、この所有者向け詳細は `/project-guide-source` で開ける。

## 起動前の前提

新しい初回準備経路では、所有者が基点・編集許可・独立した非公開テストを決めた
setup manifestから、画面で3つのworktreeを作成できる。
[設定形式・手動判断の境界・検証状況](METRON_MINI_LOCAL_VILLAGE_SETUP_2026-10-15.md)を参照する。
以下の `METRON_PROJECT_REGISTRY` による既存登録も引き続き使える。

初回の登録情報は依然として所有者によるローカル準備が必要である。
同じ Git repository の基点・候補・使い捨て適用先、編集許可、公開テスト、独立した非公開テストを
[登録契約](METRON_MINI_REGISTERED_PROJECT_SESSIONS_2026-10-15.md)に従って用意する。
この画面は任意のフォルダーやコマンドを HTTP から登録しない。
登録 JSON の作成や Git 作業領域の準備までを一般利用者のセルフサービスにしたとは主張しない。

PowerShell では、所有者が選んだ登録 JSON と既存の公式 Codex 実行ファイルを指定する。
以下の山括弧部分は実際に所有者が選んだ絶対パスへ置き換える。

```powershell
$env:METRON_PROJECT_REGISTRY = '<absolute-path-to-owner-projects.json>'
$env:METRON_CODEX_EXECUTABLE = '<absolute-path-to-codex.exe>'
$env:METRON_MINI_DATA = '<absolute-path-to-separate-mini-data>'
node mini/start.mjs
```

登録を使わない通常の `node mini/start.mjs` は従来どおり起動する。
Codex の設定は任意で、未設定なら修復候補の作成は利用できないと表示する。
設定時にも起動処理はモデル・ログイン・ネットワークの確認を実行しない。
設定済みという表示は認証やモデルの応答を保証しない。実行時に既存アダプターが確認する。

起動ログの所有者用 URL を自分の PC のブラウザーで開く。
URL の `#project-operator=` 以降は、この起動専用の操作権限であり他人へ共有しない。
画面は fragment を消してキーをページのメモリーだけに保持する。
ブラウザーの保存領域には記録しないため、再読込後は起動ログの URL を再度開くか、
所有者キー欄へ入力して登録対象を読み直す。再起動では別のキーを発行する。

## 画面で進める手順

1. 元の受信本文がなければ、Mini コンソールで無害なメッセージを送る。
   `/experience` に戻り保存状態を読み直し、村・受信本文・目的・必要な採用知識を選んで仕事を保存する。
   仕事 ID と元の本文・SHA-256 を確認する。別村には既存の Rumor 受信・採用操作から本文が届く。
2. 所有者キーを確認し、登録済み対象を選ぶ。基点 commit、編集許可、公開テスト等を読む。
   症状と公開してよい再現情報を記入し、保存した同じ仕事で公開失敗を再現する。
   テストの起動失敗・時間切れ・skip を、不具合の再現成功とは扱わない。
3. 送信範囲を読み、今回一回の Codex 実行だけに同意して候補を作る。
   画面は要求 ID を先に固定して非同期ジョブを表示する。読み取り・再読込・再起動は AI を呼ばない。
   接続不明なら保存状態を確認し、同じ要求を勝手に再送しない。
4. 候補の実差分・commit・差分ハッシュを読み、確認者名と差分確認を指定して独立検証する。
   公開失敗なら実際の失敗情報を読んで次の候補を明示的に依頼する。
   非公開判定の内容やログは AI に返さず、拒否を合格へ書き換えない。
5. 検証済みの候補・差分・検証 ID・期待 HEAD を確認し、登録済み使い捨て適用先だけへの適用を選ぶ。
   適用後テストと読み戻しを確認する。rollback も現在の HEAD と対象を確認する別操作である。
6. 共有文と公開してよい診断・適用条件・限界を記入して手元に保存し、保存した正確な内容を再確認して
   ローカル Village Square へ公開する。別村の既存画面で受信し、利用者が採用または保留を決める。
   採用した知識を次の仕事で選び、元の Rumor と検証記録の由来を確認する。

選択した村・仕事・候補・版が変われば確認チェックは失効する。
登録済み仕事では教材用の修復ボタンを使用できない。累積候補数は系譜全体で三回まで。
要件追加は別の登録を所有者が準備した後に、同じ仕事で前回成功と公開情報を保ったまま開始する。
詳細は[要件改訂契約](METRON_MINI_PROJECT_REQUIREMENTS_REVISIONS_2026-10-15.md)を参照する。

## 停止と未確認結果

停止操作は所有する worker の中断を要求し、既存の lease を無効にする。
失敗後の再開は、停止・候補・ログを人が確認して明示的に行う。
プロセス終了を確認できない状態は隔離し、自動で安全と見なさない。
再起動時の実行中ジョブは結果確認が必要な状態で残る。
この画面だけで、別プロセスに残った worker の終了を無条件に証明・解除する機能はない。

検証待ちでも停止を要求できるが、Git への適用操作は途中で取り消せない。

## 前段の画面接続確認（68f3f4a）

Windows の全回帰は 355/355 成功、失敗・取消・skip はゼロ（約16分12秒）。
凍結した画面での隔離 Chromium 確認も成功した。Console から仕事を作り、公開失敗の再現、
一つ目の候補の検証失敗、再読込、明示的な再試行、二つ目の差分確認と独立検証、
使い捨て作業領域への適用、Rumor の公開・別村での採用・次の仕事への由来を確認した。
この画面試験の worker は明記したローカル注入で、実 AI の呼出しはゼロ。
HTML には試験ドライバーを加え、配信元の HTML・JS・CSS 等8ファイルを14応答の記録と照合した。
最終成功までに試験側の待合せ不備2件を修正し、その失敗記録も保持した。

実際の起動入口でも、所有者が準備した二件の登録とインストール済み Codex のファイル情報から、
所有者限定カタログと案内文を提供できることを確認した。この起動確認では CLI 自体を実行せず、
既存の仕事・ジョブ・修理証拠を変更していない。通常利用ブラウザーや Codex アプリの再起動は行っていない。

承認済みの合成案件 `prefix-gateway-v2` と `delivery-envelope-v2` を、隔離 Chromium の実画面と

公開・非公開検証、登録済み使い捨て作業領域への適用、適用後テスト、保存状態の読み戻しが成功した。
候補生成・検証・適用はそれぞれ別の Mini 起動で、再起動時の読み取りによる追加 AI 呼出しはゼロ。
Windows の全回帰は 364/364 成功、失敗・取消・skip はゼロだった。
対象選択カード・送信範囲確認・起動 URL の同一ページ再接続・読みやすい案内も確認した。

両案件は既知の合成 shape の再利用であり、未知案件への一般化を示さない。
通常の CLI 運用指示文書も読まれているため、読み取りが案件内だけだったとは主張しない。

## 完成基準に対する範囲

- 既存の村・Gateway・仕事・共有を使い、登録済み修復を画面の操作で進める経路を接続する。
- 前段の UI 確認は明記した試験用 worker、今回の二件は公式 Codex CLI を使う。
  どちらも隔離 Chromium であり、利用者の通常ブラウザーの確認とは区別する。
- 前段の二件の実 Codex 証拠は[要件改訂記録](METRON_MINI_PROJECT_REQUIREMENTS_REVISIONS_2026-10-15.md)に残る。
  今回の二件は実 AI を含む登録済み修復の UI 経路まで確認したが、全用途の E2E を意味しない。
- 通常ログイン済み ChatGPT の ARC、初回登録のセルフサービス化、登録済み修復での別実 AI への代替、
  修復検証と PoUC 台帳の結合、PC 全体の再起動・本番適用・実運用故障の BAKU 修復は残る。
- 原構想の自己修復・自己複製・自律進化は、実コード修復、許可された新村の起動と継承、
  経験から候補を実評価して採用・復元する循環として評価する。記憶保存だけへ縮めない。
