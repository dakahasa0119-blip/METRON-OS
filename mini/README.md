# METRON Mini OS — 起動できる最小の4系統統合

## Miniの実モデル駆動BAKU修復経路

`/experience` 第10章には、2ファイルにまたがる壊れた
ミニプロジェクトを、**実際のAIコーディングモデル**に読ませて
修正させる機能があります。モデルはソースと失敗した公開テストを
読み、JSON形式で差分を提案します。BAKUが使い捨てコピーへ適用し、
独立したNodeプロセスで実テストを実行します。失敗するとテスト
結果と履歴をモデルへ再送し、最大3回まで修正候補を試します。
公開テスト通過後、AIに見せていない別のテストで合否を検証します。

使用には `METRON_LOCAL_MODEL` を設定した本物のOllamaモデル、
または `OPENAI_API_KEY` と `METRON_REPAIR_MODEL` を設定した
OpenAI APIが必要です。OpenAIを選択する場合はその実行ごとに
外部送信と課金の可能性への承諾が必要です。モデルが未接続なら
「未実行」として止まり、固定文章で代用しません。

現在は**同梱の信頼された2ファイルの練習用プロジェクトだけ**が
修復対象です。実プロジェクトの未知の問題を自在に修正できる
本番用ツールではありません。モデルなしのテストでは模擬応答を
使いますが、実ビルド・失敗・再テスト・履歴保存は本物です。

[実装・検証証拠と制約](../docs/BAKU_AGENTIC_MINI_RUNNER_2026-10-14.md)

## BAKUの本体は「AIが開発者として修復する」こと

BAKUの本来の修復は、現在ChatGPTがGitHubやPCのIDEを操作して
行っている作業と同じです。**実際のAIがソースを調べ、原因を推論し、
複数ファイルを修正し、コンパイル・実動作・回帰テストを実行し、
失敗結果を使って修正し直し、証拠を残して安全に反映すること**です。

以下の「単一関数の演算子探索」と「既知正常版からの復元」は
BAKUの補助モジュールであり、完全な自己修復を実現した
ことにはなりません。現行Miniには、実AIと承認済みPC/IDE
実行経路を使ってこの作業を完結するエージェントループは
まだ実装されていません。

[BAKU本体の実装・検証契約](../docs/BAKU_AGENTIC_REPAIR_CONTRACT_2026-10-14.md)

## 正常版が存在しない不具合の探索

今回追加した `/experience` 第09章では、不具合を含む短い
JavaScript関数と、**失敗を再現する入出力テスト**、別の確認用
テストを与えます。BAKUの修復探索器は正解のソースを参照せず、
演算子・境界条件・論理演算・数値定数を変更した候補を探索し、
独立した確認用テストを通過した場合だけ修正候補を提示します。
候補は使い捨ての一時ファイルで読み戻し、SHA-256も確認します。

対応は単一の純粋な関数・単一return式に限定されます。
任意のJavaScriptの実行、本番コードの変更、未知の複雑な障害の
全面的な解決、外部AIの認証済み修正提案は**未実装**です。
対応外・未解決・確認失敗の場合はその理由を表示します。

[実装範囲・5種類の未知故障テスト・失敗時の扱い](../docs/UNKNOWN_BEHAVIORAL_REPAIR_2026-10-14.md)

## 原構想にある4機能の実行経路（追加）

外部AI三者合議には、**本物の**OpenAI・Gemini・Claudeの独立した回答が必要です。
それぞれの公式APIキー・モデル名がNode.jsの環境変数に設定され、
各リクエストで利用者が外部送信を許可した場合にだけ問い合わせます。
いずれかが不足すれば合議不成立と表示します。利用料金が発生する可能性があります。

ローカルLLMは任意です。従来の合議API経路では、上記3件の回答が揃った後に、
localhost上の**本物のOllamaモデル**へ依頼します。
METRON_LOCAL_MODELでモデルを指定します。ローカルモデルが動いていない場合でも、能力を満たす別のAIへの代替を認める設計です。ただし、その代替経路はすべての画面・合議処理へ統合済みではありません。
APIキー・モデル名をサンプルのまま勝手に補完したり、モデルの結果を固定文で代用したりしません。

PoUCでは、構文検査・BAKUコードDNA解析などの有用な計算を実行し、
ハッシュ付き証拠を**再計算**してローカルの貢献履歴へ保存します。
暗号通貨・現金・分散型マイニング報酬は提供しません。

BAKUの自動復旧は、隔離一時領域に故障を発生させ、
**実際に検出→既知正常版へ復旧→構文とSHA-256の再検証**を行います。
本番環境の未知の故障を自動解決できるものではありません。

詳しい構成、接続手順、実装範囲は
[AI合議・PoUC・BAKUの実行境界](../docs/AI_POUC_RECOVERY_EXECUTION_2026-10-14.md)
を参照してください。

## 最初に見てほしいのは「構想の体験」

`node mini/start.mjs` で起動したら、まず
**http://127.0.0.1:8766/experience** を開いてください。

- **一つの村の中に母艦Aと母艦Bがあります。** A/Bは別の村ではありません。
- 各村はそれぞれ母艦A/BとGatewayの保存データを持ちます。
- 第一の村が**実際のRumor JSONファイル**をVillage Squareに公開します。
- 第二の村のGatewayがそのファイルを受信してから、利用者が知識を「採用」または「隔離」します。
- Gatewayのノイズ検査強度は利用者が設定し、最終判断も利用者が行います。
- 第二の村から第一の村への共有も同じRumorプロトコルを使用します。
- BAKUは入力されたコードから断片を実際に抽出しますが、コードを実行・修復したとは主張しません。

**外部AI三者合議とローカルLLM最終判断は任意の実モデル認証・接続が必要です。** PoUCはローカルで検証可能な計算・証拠記録まで実装済みですが、分散型マイニングは未実装です。
固定規則による作文でそれらを代替したことにはしません。
以前の体験データは上書きせず、旧`civilization.json`に残します。
詳細は[METRON構想の体験設計](../docs/METRON_CIVILIZATION_EXPERIENCE_2026-10-14.md)を参照してください。


**これは実際に起動して操作できるローカルWebアプリです。** これまで
個別に実証した母艦A/B・Gateway・BAKU・ARCの機能を、1つの画面から
試せるようにしています。外部AI・Google Apps Script・Android端末・
クラウドAPIへの接続は行いません。

## 起動する

Node.js 20以上が必要です（追加パッケージは不要）。

```sh
git clone https://github.com/dakahasa0119-blip/METRON-OS.git
cd METRON-OS
node mini/start.mjs
```

Windowsなら、[**START_WINDOWS.cmd**](START_WINDOWS.cmd) をダブルクリックする方法もあります。Node.jsが利用可能な場合、ローカルサーバーを別ウィンドウで起動して標準ブラウザを開きます。終了時はサーバーのコマンドウィンドウを閉じてください。

ブラウザで **http://127.0.0.1:8766/** を開いてください。

1. 母艦Aから母艦Bへメッセージを送ります。
2. Gatewayがジョブを永続化し、Bの独立保存ファイルへ配送します。
3. BからAへのACK（配達確認）が自動的に発行され、A側に記録されます。
4. BAKUが同じリクエストに入っているコード断片を静的検査し、関数名・注意候補を表示します（コード自体は**実行・保存しません**）。
5. ARCがこのローカル画面上の入力欄・送信ボタン・受信欄のDOMを探索します。「入力欄を選択」などで手動ピッカーも操作できます。
6. プログラムを停止・再起動し、保存されたメッセージとGateway状態が残っていることを確認できます。

**注意:** 母艦A/BはローカルJSONファイルで、過去のGoogle Sheetsの
2母艦が通信したことを証明するものではありません。ARCの従来のローカルDOM探索はこのページ内で動きます。通常ログインしたChatGPTのUIを手動選択する拡張機能は別途 `mini/arc-browser/` にあり、外部AIへの自動送信・回答取得はまだ実装されていません。BAKUには限定的な候補探索と、モデル認証時に使える隔離された複数ファイル修復ワーカーがありますが、任意の未知障害を完全自律修復するものではありません。

## 使われる構成

| 領域 | 実体 | 状態 |
| --- | --- | --- |
| MotherShip A | `.metron-mini-data/mother-A.json` | 独立した受信履歴 |
| MotherShip B | `.metron-mini-data/mother-B.json` | 独立した受信履歴 |
| Gateway | `.metron-mini-data/gateway.json` | ジョブ・ACK・リース・再起動復旧 |
| BAKU | `reusable/baku-dna/code-cards.mjs` | 非実行の関数抽出と注意候補 |

| 母艦ワークフロー | `reusable/mothership/workflow.mjs` | 指示の分類補助 |

## 制限・安全境界

- HTTPサーバーは**127.0.0.1のみにバインド**。認証・遠隔接続・
  システム権限委譲はありません。信頼できる自分のPCだけで使用してください。
- メッセージはローカルJSONに保存されます。機密情報を入力しないでください。
  コード本文は保存しませんが、検出した関数名・静的検査結果は記録されます。
- **同じ保存ディレクトリに対して同時に2つ起動しないでください。**
  ファイルの単一書き込みプロセスを前提にしています。
- メッセージ再送時の重複抑止はJSON受信記録が基準です。外部の
  副作用をexactly-onceにする保証はありません。
- ブラウザ操作は利用者の明示的なクリックに限定。ログインや
  第三者AIの画面・CAPTCHA操作は提供しません。
- このプロトタイプは**本番用の認証、暗号化、長期バックアップ、
  完全自動AI推論、自己修復、4系統の歴史的な全統合**を実証しません。

## オプションとテスト

別のデータ場所・ポートで起動できます。

```sh
# Linux/macOS
METRON_MINI_DATA=/path/to/my-private-data METRON_MINI_PORT=8877 node mini/start.mjs

# Windows PowerShell
$env:METRON_MINI_DATA="C:\\MyPrivateData\\MetronMini"
$env:METRON_MINI_PORT="8877"
node mini/start.mjs
```

テスト:

```sh
node --test reusable/tests/mini-runtime.test.mjs
node --test reusable/tests/*.test.mjs
```

## 追加の復旧検証

自動試験では、母艦A/Bの逆方向配送、配達保存直後にGatewayが停止してACKを受け取れなかった状況、再起動後の再送・重複抑止、コードの一時検査、実ChromiumによるARCのDOM探索を扱います。
